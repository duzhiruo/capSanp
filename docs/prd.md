## 01 · 产品定位
### 1.1 为什么聚焦「照片/截图」
当人们说"信息管理太乱"，每个人脑海里最先浮现的画面几乎一样——**相册里那几千张没整理过的截图**。它们是被忽视最久、痛苦最深、却从未被认真解决的数字垃圾。

> **核心决策**：MVP 只做一件事——**让用户手机相册里的截图变得可以被搜索**。第一阶段不追求完整 AI 管家体验，先用「导入截图 → 本地 OCR → 关键词搜索 → 找到原图」验证核心价值；确认用户真的会回来搜索后，再逐步加入自动分类、摘要和语义搜索。
>

### 1.2 产品本质（三个关键词）
| 关键词 | 含义 |
| --- | --- |
| **📸**** 截图是输入** | 用户截图行为不变。CapSnap 尽量复用系统相册中的截图资产，减少额外整理成本 |
| **🧠**** OCR 是起点** | 先把截图里的文字稳定提取出来，再逐步扩展到分类、标签、摘要和语义理解 |
| **🔍**** 搜索是价值交付** | "上次那个" → 快速出结果。这个「找到了」时刻就是用户留下来的理由 |


### 1.3 一句话定位
> **CapSnap** 是手机截图的智能搜索工具——把截图里的文字提取出来，帮你用关键词和自然语言找到那些"记得存过但找不到"的图。
>

### 1.4 MVP 边界（明确不做的事）
| 不在范围内的功能 | 原因 | 未来版本 |
| --- | --- | --- |
| 链接/网页收藏 | 进入成本高、抓取策略复杂，分散 MVP 验证焦点 | v1.1 |
| 文本笔记输入 | 与截图场景用户动机不同，MVP 不混合 | v1.1 |
| 多端实时同步 | 存储和冲突解决复杂，MVP 只做本地 | v1.2 |
| 强实时后台监听 | iOS 后台能力受系统限制，不能承诺每张截图实时处理 | 后续按系统能力优化 |
| 云端 AI 默认处理 | 隐私信任是早期关键，默认不上传截图内容 | 用户主动开启增强模式后再评估 |
| 团队/协作功能 | 个人价值未验证前不考虑协作 | v2.0 |
| 图片编辑/标注 | 那是另一个产品方向（截图工具），我们只做归档和检索 | —— |
| 生活照片（人物/风景）整理 | Google Photos 等已做得很成熟，我们聚焦"截图"细分场景 | v2.0 再评估 |

## 02 · 用户洞察
### 2.1 目标用户画像
#### Persona A：知识型工作者 👩‍💼
| 维度 | 描述 |
| --- | --- |
| **身份** | 产品经理、设计师、运营、市场——需要在工作中快速捕捉和回顾信息 |
| **截图频率** | 每天 10–30 张 |
| **截图类型** | 竞品 UI、数据报表、聊天记录的决策、灵感参考 |
| **核心痛点** | 三天前截的竞品定价页找不到了，聊天记录里老板说的需求截图被自拍淹没了 |
| **代表性原话** | _"我相册里有 3000 多张截图，有用的起码一半，但找到某一特定的得翻到哭"_ |


#### Persona B：内容创作者 🎨
| 维度 | 描述 |
| --- | --- |
| **身份** | 博主、自媒体、独立开发者——大量收集灵感和素材 |
| **截图频率** | 每天 20–50 张 |
| **截图类型** | 设计灵感、文案参考、排版参考、行业资讯 |
| **核心痛点** | 收藏了就是积累——但从来没整理过。做内容时想引用某张图，翻半小时找不到 |
| **代表性原话** | _"我小红书的收藏和相册截图加起来快一万条了，全靠运气找"_ |


#### Persona C：职场多线程人 📊
| 维度 | 描述 |
| --- | --- |
| **身份** | 项目经理、销售、咨询——需要频繁截图并事后跟进 |
| **截图频率** | 每天 5–15 张 |
| **截图类型** | 会议白板、报价单、合同条款、方案对比 |
| **核心痛点** | 截图拍了就当"记住了"，一周后完全不记得截过，更找不到 |
| **代表性原话** | _"客户给我报了个价我截图了，后来要查——截没截图都不确定了"_ |


#### Persona D：兴趣学习者 📚
| 维度 | 描述 |
| --- | --- |
| **身份** | 学生、自我提升者——用截图当"知识书签" |
| **截图频率** | 每天 5–10 张 |
| **截图类型** | 书摘、课程笔记、教程截图、好词好句 |
| **核心痛点** | 截图是最快的"记笔记"方式——但它完全不可检索 |
| **代表性原话** | _"Kindle 高亮还能导出呢，我截的书摘连 OCR 都没有"_ |


### 2.2 用户行为的四个阶段
```plain
截图行为 → 即时遗忘 → 偶尔想起 → 翻相册 → 放弃
            ↑____________________________|
            
            "算了不想找了" — 这是最大的流失信号
```

绝大多数用户在「翻相册」这一步就放弃了——不是因为信息不存在，而是因为**检索成本高于信息价值**。当这个循环重复足够多次，用户就会养成"截图但不指望找到"的习惯——然后我们的获客成本就会指数级上升。

### 2.3 关键洞察
+ **截图是「最小摩擦的信息保存」行为**——比打字快、比复制粘贴简单、比收藏夹省心
+ **但截图的代价是「不可检索」**——这是天然矛盾：存得越容易，找起来越难
+ **用户不会主动整理**——要求用户改变行为的产品会死。CapSnap 存在的价值就是：在你不需要改任何习惯的前提下，让截图变得可检索

## 03 · 需求挖掘
### 3.1 核心痛点清单
| # | 痛点 | 严重程度 | 频次 |
| --- | --- | --- | --- |
| 1 | 截图和自拍混在一起，搜索相册时被无关内容淹没 | 🔴 极高 | 每天 |
| 2 | 记得"截过这张图"但翻不到——放弃寻找 | 🔴 极高 | 每周 2–3 次 |
| 3 | 截图里的文字无法被搜索——相册只能按时间找 | 🔴 极高 | 每次需要时 |
| 4 | 不知道截图里有什么——不打开就不知道内容 | 🟡 高 | 每天 |
| 5 | 临时截图（一次性信息）和重要截图混在一起 | 🟡 高 | 每周 |
| 6 | 截图来源无从追溯——不知道是哪个 app/谁的聊天 | 🟡 高 | 偶尔 |
| 7 | 相似截图多张（同一场景多次截取），不知道哪个是最终版 | 🟡 中 | 偶尔 |
| 8 | 截图积压带来心理负担——"我该整理了"但从来没行动 | 🟡 中 | 每周 |
| 9 | 换手机时截图迁移后彻底混乱 | 🟢 低 | 1–2 年一次 |
| 10 | 想分享某张截图给别人但找不到 | 🟡 高 | 每周 |


### 3.2 截图场景细分（决定了 AI 理解的难度）
| 截图类型 | 占比估算 | 典型内容 | AI 理解难度 | 检索需求 |
| --- | --- | --- | --- | --- |
| **UI/界面截图** | 30% | App 页面、网页、设置界面 | 中等 | 按功能/App 名称搜索 |
| **文字/文章截图** | 25% | 推文、文章、聊天记录 | 低（可 OCR） | 按关键词/主题搜索 |
| **数据/图表** | 10% | 数据表格、KPI 看板、趋势图 | 高 | 按数据内容搜索 |
| **聊天对话** | 15% | 微信/钉钉/飞书对话 | 中等（OCR + 关系识别） | 按对话内容/联系人搜索 |
| **图片/设计参考** | 10% | 海报、Logo、穿搭、装修 | 高（纯视觉理解） | 按风格/用途搜索 |
| **文档/表格** | 5% | 合同、报价单、协议 | 低（结构化 OCR） | 按文档类型+关键字段搜索 |
| **二维码/条形码** | 3% | 付款码、名片、WiFi 密码 | 极低 | 按二维码类型搜索 |
| **混合/无法归类** | 2% | —— | —— | —— |


> **产品决策**：MVP 优先做好「文字/文章」「UI/界面」「聊天对话」三类截图的理解——它们合计占比 70%，且技术难度相对可控。数据图表和纯视觉内容放到 v1.1 优化。
>

### 3.3「搜索」需求的四种模式
| 模式 | 用户心里想的 | 系统需要做的 |
| --- | --- | --- |
| **主题搜索** | "上次那个竞品定价的截图" | 语义理解 → 匹配分类+标签+摘要 |
| **来源搜索** | "跟 XX 聊天截图里的那个地址" | OCR 文字提取 → 关键词匹配 |
| **时间搜索** | "上周三那个会议的板书" | 时间范围过滤 + 内容理解 |
| **关联搜索** | "跟上次那个产品介绍相关的截图" | 图片相似度 + 语义关联推荐 |

## 04 · 功能设计
### 4.1 版本切分总览
| 阶段 | 目标 | 核心验证 |
| --- | --- | --- |
| **v0.1 — OCR 搜索验证版** | 做出最小可用闭环 | 用户导入截图后，能否用关键词快速找到目标截图 |
| **v0.2 — 自动归档可用版** | 降低持续使用成本 | App 打开时能自动发现新增截图，并稳定进入处理队列 |
| **v0.3 — AI 增强体验版** | 提升搜索和浏览体验 | 自动标签、粗分类、摘要是否显著提高找图效率 |
| **v1.0 — TestFlight 公测版** | 面向种子用户验证留存 | 隐私、性能、搜索体验是否足够稳定 |


### 4.2 v0.1 功能（第一阶段必须）
#### F-01：手动导入截图
| 属性 | 说明 |
| --- | --- |
| **功能描述** | 用户通过系统相册选择器手动导入一批截图，进入本地处理队列 |
| **用户感知** | 第一次使用时选择 20–200 张截图，等待处理完成后即可搜索 |
| **关键交互** | 首页提供「导入截图」入口；支持多选；导入后展示处理进度 |
| **异常处理** | 用户拒绝全量相册权限时，仍可通过系统选择器导入指定图片 |
| **依赖** | iOS PhotosUI / Photos 权限 |


#### F-02：本地 OCR 文字识别
| 属性 | 说明 |
| --- | --- |
| **功能描述** | 使用本地 OCR 提取截图中的文字，保存为可搜索文本 |
| **用户感知** | 处理完成后，详情页可查看和复制 OCR 文字 |
| **质量要求** | 中文屏幕文字识别整体可用；第一版不承诺复杂字体、竖排文字、低清图片的高准确率 |
| **隐私承诺** | 默认不上传原图和 OCR 内容 |
| **依赖** | iOS Vision 框架或等价本地 OCR 能力 |


#### F-03：本地关键词搜索
| 属性 | 说明 |
| --- | --- |
| **功能描述** | 输入关键词，在已导入截图的 OCR 全文中检索 |
| **搜索范围** | OCR 全文 + 截图时间 |
| **用户感知** | 搜索结果展示缩略图、截图时间和命中的文字片段 |
| **结果排序** | 第一版按匹配度和时间排序，优先保证稳定和可解释 |
| **依赖** | 本地数据库全文索引（如 SQLite FTS） |


#### F-04：时间线浏览
| 属性 | 说明 |
| --- | --- |
| **功能描述** | 按时间倒序展示所有已处理截图 |
| **用户感知** | 默认首页展示最近导入和最近截图，符合用户相册浏览习惯 |
| **状态展示** | 处理中、处理失败、已完成三种状态必须清晰 |


#### F-05：截图详情页
| 属性 | 说明 |
| --- | --- |
| **功能描述** | 点击任意截图卡片，进入详情页查看原图和识别文本 |
| **展示信息** | 原图（可缩放拖拽）、OCR 全文、截图时间、处理状态 |
| **操作** | 支持复制 OCR 文字、分享原图、从知识库移除 |
| **边界说明** | 第一版不承诺可靠识别来源 App，只展示系统可获得的时间和图片信息 |


#### F-06：基础设置页
| 属性 | 说明 |
| --- | --- |
| **功能描述** | 用户可查看和管理基础数据 |
| **设置项** | 数据统计、重新处理失败项、清空本地索引、隐私说明、关于 |


### 4.3 v0.2 功能（自动归档可用版）
| 功能 | 描述 | 价值 |
| --- | --- | --- |
| F-07：截图相簿扫描 | App 打开时扫描系统「屏幕截图」相簿，发现新增截图 | 降低持续导入成本 |
| F-08：增量处理队列 | 只处理新增或失败重试的截图 | 避免重复 OCR 和性能浪费 |
| F-09：后台处理尽力而为 | 在系统允许的后台时间内继续处理队列 | 改善体验，但不承诺强实时 |
| F-10：批量处理完成通知 | 首次扫描或批量处理完成后通知用户 | 让用户感知价值，避免逐张打扰 |
| F-11：仅 Wi-Fi / 充电时处理偏好 | 控制处理时机，降低耗电焦虑 | 提升信任 |


### 4.4 v0.3 功能（AI 增强体验版）
| 功能 | 描述 | 价值 |
| --- | --- | --- |
| F-12：规则/轻量模型自动标签 | 从 OCR 中提取品牌名、金额、日期、联系人等实体 | 提升筛选效率 |
| F-13：粗粒度自动分类 | 将截图建议归入聊天、文档、购物、产品参考等分类 | 改善浏览体验 |
| F-14：一句话摘要 | 为截图生成 60 字以内摘要 | 降低打开图片确认成本 |
| F-15：自然语言语义搜索 | 支持用模糊描述搜索截图 | 提供惊喜感，但不作为第一阶段核心 |
| F-16：AI 增强模式开关 | 用户主动开启后，可选择更强的云端或本地模型能力 | 在隐私和效果之间给用户选择 |


### 4.5 v1.0 功能（TestFlight 公测前补齐）
| 功能 | 描述 | 价值 |
| --- | --- | --- |
| F-17：分类/标签修正 | 用户可修正 AI 建议分类和标签 | 建立信任 |
| F-18：批量修正 | 多选截图后批量修改分类/标签 | 降低整理成本 |
| F-19：相似截图去重建议 | 识别疑似重复截图，建议保留最佳 | 减少冗余 |
| F-20：数据导出 | 导出截图索引和 OCR 文本为 JSON/ZIP | 增强数据安全感 |
| F-21：定期清理建议 | 每周智能推荐临时截图 | 解决积压焦虑 |


### 4.6 v1.1+ 功能（增长与扩展）
| 功能 | 描述 |
| --- | --- |
| F-22：Widget 小组件 | 桌面小组件显示最近截图和快捷搜索入口 |
| F-23：截图周报 | 每周推送"这周你截了 XX 张图，主要集中在 XX 领域" |
| F-24：截图合集 | 手动创建主题合集，将相关截图归入同一个集合 |
| F-25：Siri 快捷指令 | 说"搜索我的截图：竞品定价"直接打开搜索结果 |
| F-26：链接/笔记接入 | 扩展信息入口 |
| F-27：iPad / macOS 适配 | 大屏和桌面端优化 |
| F-28：Pro 订阅 | 解锁高级 AI 能力、批量处理和跨端能力 |

## 06 · 核心交互流程
### 6.1 首次使用（v0.1 Onboarding）
```plain
流程：欢迎页 → 选择导入方式 → 手动选择截图 → 本地 OCR 处理 → 进入首页

步骤 1：欢迎页

  ├── 展示 3 个使用场景插画
  └── 点击「开始使用」

步骤 2：选择导入方式
  ├── 推荐：「先选择一批截图试试」
  ├── 说明：「默认本地 OCR，不上传原图和识别文本」
  └── 用户打开系统相册选择器

步骤 3：手动选择截图
  ├── 建议选择 20–200 张截图
  ├── 可从系统「屏幕截图」相簿中选择
  └── 不强制授予全量相册权限

步骤 4：本地 OCR 处理
  ├── 显示处理进度（如 50 张截图 → 预计几十秒到数分钟，视设备而定）
  ├── 已完成的截图可立即浏览和搜索
  └── 失败项可稍后重试

步骤 5：进入首页
  ├── 展示已处理截图数量
  ├── 顶部搜索框引导：「试试搜索"竞品"」
  └── 时间线展示已导入截图
```

### 6.2 日常存入（v0.2 自动扫描）
```plain
用户截图 → 打开 CapSnap → App 扫描「屏幕截图」相簿 → 
发现新增截图 → 加入处理队列 → 本地 OCR → 更新索引

用户感知：无需每次手动导入，但不承诺截图后立即后台处理。
首次扫描或批量处理完成时可通知，避免逐张通知打扰用户。
```

### 6.3 搜索检索（高频价值时刻）
```plain
场景：用户三天前截过一张竞品定价页，现在写报告需要引用

流程：
  ├── 打开 CapSnap 首页
  ├── 点击顶部搜索框 → 输入："竞品定价"
  ├── 搜索结果：
  │   1. 📸 3天前 — 命中片段："竞品A SaaS 定价页，基础版 $29/月"
  │   2. 📸 1周前 — 命中片段："竞品B 企业版报价单"

  ├── 点击结果 1 → 进入详情页
  ├── 查看原图 + OCR 文字 → 复制关键数据
  └── 完成。总耗时 < 10 秒。
```

### 6.4 修正分类/标签（v1.0 AI 容错闭环）
```plain

流程：
  ├── 用户在浏览时注意到分类错误
  ├── 进入详情页
  ├── 点击「修正分类」→ 弹出分类选择器
  ├── 选择「聊天记录」→ 即时更新
  ├── 系统记录：用户将「文档资料」修正为「聊天记录」
  └── 修正数据用于后续改进分类规则或模型

用户感知：AI 错了没关系，花 3 秒改正就好。而且感觉 App 在"学习"自己的习惯。
```

### 6.5 定期清理（v1.0 主动建议）
```plain
流程：
  ├── 每周日晚 20:00，CapSnap 推送通知：
  │   "本周你新增了 47 张截图。其中 12 张可能是临时内容（快递截图、验证码等），要清理吗？"
  ├── 用户点击通知 → 进入清理建议列表
  │   ├── 快递单截图 × 3
  │   ├── 验证码截图 × 2
  │   ├── 临时备忘 × 5
  │   └── 模糊/重复截图 × 2
  ├── 用户可逐张确认删除，或「一键清理全部建议」
  ├── 删除前二次确认：「已选择 12 张，确认删除？这些内容将在 30 天后从回收站彻底清除」
  └── 完成后：「已清理 12 张，释放 XX MB。下周见 👋」
```

## 07 · 用户故事
### US-01：手动导入一批截图（v0.1）

+ 支持从系统相册选择器多选截图
+ 导入后显示处理进度和失败数量
+ 用户拒绝全量相册权限时，仍可完成手动导入

### US-02：关键词搜索截图内容
> **作为**需要频繁回头找信息的职场人，  
**我希望**输入关键词就能在所有截图的文字中搜索，  
**以便**我能快速定位那张我记得"里面有 XX 信息"的截图。

**验收标准**：

+ 搜索结果在 1 秒内返回
+ 匹配关键词高亮展示
+ v0.1 搜索范围至少包含 OCR 全文和截图时间

### US-03：查看截图完整信息
> **作为**需要确认截图完整内容的用户，  
**我希望**在详情页看到原图、识别出的文字和截图时间，  
**以便**我不需要打开原相册就能获取关键信息。

**验收标准**：

+ 原图支持双指缩放和拖拽
+ OCR 文字以段落展示并支持复制
+ 清晰展示截图时间和处理状态
+ 不承诺准确展示来源 App，仅在后续版本中展示 AI 推测来源

### US-04：自动发现新增截图（v0.2）
> **作为**持续使用 CapSnap 的用户，  
**我希望**打开 App 时能自动发现最近新增的截图，  
**以便**不用每次手动选择图片。

**验收标准**：

+ 用户授权后，App 可扫描系统「屏幕截图」相簿

**以便**不需要回忆精确关键词也能找到。

**验收标准**：

+ 支持中文自然语言输入
+ Top 5 结果中至少 1 个与查询意图匹配
+ 无结果时提供相关建议标签供二次搜索

### US-06：按分类浏览（v0.3）
> **作为**想集中查看某类信息的用户，  
**我希望**按分类（产品参考、竞品信息、聊天记录等）浏览截图，

## 08 · UI 设计原则
### 8.1 三大设计原则
| 原则 | 说明 | 体现 |
| --- | --- | --- |
| **低风险试用** | 用户可以先导入一批截图体验价值，不被迫一次性授权全部相册 | 手动导入、本地 OCR、清晰隐私说明 |
| **渐进信任** | AI 的分析结果是"建议"而非"判定"，用户始终可以修改 | 修正入口显眼、低置信度标记灰色 |
| **搜索即入口** | 搜索框是最高频的交互，必须触手可及 | 首页顶部固定、搜索独立 Tab |


### 8.2 关键界面规范
+ **截图卡片**：缩略图比例保持原图 16:9 或自适应；v0.1 优先展示时间和处理状态，v0.3 再展示摘要和分类标签
+ **搜索体验**：搜索框在所有关键页面可见，结果页支持关键词高亮，无结果时提示尝试其他关键词
+ **详情页**：原图全屏可缩放，信息卡片区域清晰分层；v1.0 再强化分类和标签修正入口
+ **AI 处理状态**：在列表中用细微的加载动画标注"处理中"的截图，已完成的不额外标注
+ **首次引导**：不超过 3 屏，重点传达"先选一批截图试试，默认本地处理"

### 8.3 品牌调性
| 维度 | 方向 |
| --- | --- |
| **视觉风格** | 明亮、简洁、有呼吸感。不要让用户觉得"又来了一个要整理的工具" |
| **文案风格** | 温和、有趣、不严肃。AI 反馈可以用带表情的语气，降低技术感 |
| **品牌色** | 主色一款温和的紫色/蓝色系，传达「智能」而非「冰冷」 |
| **品牌联想** | 蝴蝶 🦋 — "轻盈地穿梭于你的信息花园，不打扰，但需要时总在" |

## 09 · 成功指标
### 9.1 北极星指标
> **「目标截图找回率」≥ 60%（v0.1 种子测试）**  
定义：用户带着明确目标发起搜索后，能在 10 秒内找到目标截图的会话占比。  
衡量的是："我搜了，我找到了"这个核心价值是否成立。
>

### 9.2 v0.1 关键验证指标
| 指标 | 类型 | 目标值 | 说明 |
| --- | --- | --- | --- |
| 首次导入完成率 | 激活 | ≥ 70% | 进入导入流程后，成功导入并处理至少 20 张截图 |
| 目标截图找回率 | 北极星 | ≥ 60% | 用户带着目标搜索时，能找到目标截图 |
| 平均找图耗时 | 效率 | < 10 秒 | 从输入关键词到打开目标截图 |
| OCR 可用率 | 质量 | ≥ 80% | 用户认为 OCR 文本足够用于搜索的截图占比 |
| 一周内主动搜索用户占比 | 留存 | ≥ 30% | 种子用户一周内至少主动搜索 2 次 |
| 卸载/停用原因 | 定性 | 明确 Top 3 | 通过访谈了解不用的原因 |


### 9.3 v1.0 成长指标
| 指标 | 类型 | 目标值 | 说明 |
| --- | --- | --- | --- |
| 搜索有点击率 | 北极星 | ≥ 70% | 搜索后点击至少一个结果的比例 |
| 首日留存 | 留存 | ≥ 35% | 安装次日回访，种子用户阶段不追求过高 |
| 7 日留存 | 留存 | ≥ 20% | 安装后第 7 天回访 |
| 分类修正率 | 信任 | ≤ 20% | AI 分类被用户修改的比例 |
| 截图处理量/用户 | 使用深度 | ≥ 100 张 | 平均每位用户已处理的截图数 |
| 清理建议采纳率 | 主动价值 | ≥ 25% | 用户接受了清理建议的比例 |
| 评分与评价 | 口碑 | ≥ 4.5 星 | App Store 公开版本再启用 |


### 9.4 护栏指标（不能恶化）
| 指标 | 警戒线 | 说明 |
| --- | --- | --- |
| 崩溃率 | < 1% | App 稳定性 |
| 单张 OCR 处理耗时 | 可接受 | 不按绝对秒数承诺，按设备分层记录 |
| 存储占用 | < 500MB | App 总体存储占用，尽量只保存索引和必要缩略图 |
| 电池影响 | 无明显感知 | 后台处理不显著增加耗电，v0.1 先以前台处理为主 |
| 隐私投诉 | 0 | 无用户投诉数据泄露或隐私问题 |

| --- | --- | --- |
| H1 | 用户愿意先手动导入 20 张以上截图试用 | v0.1 导入完成率 |
| H2 | 用户每周至少遇到 1 次「找截图找不到」 | 用户访谈 + 问卷调查 |
| H3 | 本地 OCR 足以覆盖大部分中文截图搜索需求 | OCR 可用率 + 搜索找回率 |
| H4 | 用户会因为能找回截图而一周内主动回来搜索 | 一周内主动搜索用户占比 |
| H5 | 自动扫描新增截图能显著降低持续使用成本 | v0.2 留存和访谈 |
| H6 | AI 标签/分类/摘要能显著缩短找图时间 | v0.3 前后对比测试 |
| H7 | 用户愿意为更强 AI 能力或跨端能力付费 | v1.0 后付费意愿访谈 |

## 附录 B：术语表
| 术语 | 定义 |
| --- | --- |
| 截图 | 用户在手机上通过按键组合（如音量+电源）截取的屏幕图像 |
| 知识库 | CapSnap 中用户所有已处理截图的集合 |
| AI 理解 | 对截图进行 OCR、标签、摘要、分类和语义搜索的完整处理流程；v0.1 仅包含 OCR |
| 语义搜索 | 基于自然语言描述的搜索，不依赖精确关键词 |
| 分类修正率 | AI 分类被用户手动修改的比例，用于衡量 AI 准确度 |
| 临时截图 | AI 判断为一次性使用的截图（如快递单、验证码、临时备忘） |
